## 2. 数据画像（Laws-1.0.0）

- 正文在 **Markdown**，按部门目录组织；`db.sqlite3` 仅存分类表 `category`（26 部门），不含正文。
- 法条文件结构：`# 法律全名` → 立法沿革（通过/历次修正日期 + 机关）→ `<!-- INFO END -->` → 正文（`第X条 …`）。
- 命名 `名称(日期).md`；同一法律可能多版本（带日期的历史版与无日期的当前版并存，如 `刑法.md` 与 `刑法(2020-12-26).md`）。
- 含 Obsidian 标记（`bookCollapseSection` 等），解析时需过滤。

## 4. 接入与本体

- **解析器**：读 md；每个文件产出：法律全名、部门分类、颁布日期、历次修正日期、效力层级、条文列表（`第X条` 拆分）。过滤 Obsidian 标记与 `<!-- INFO END -->`。
- **领域本体** `cnlaw/ontology/law.ttl`（新增）：
  - 实体：`LegalDocument`、`Article`、`LegalCategory`、`EnactingBody`、`LegalLevel`
  - 属性：`name`、`full_name`、`promulgated_date`、`amended_date`、`legal_level`、`status`（现行有效/已被修订/已废止/待核验）
  - 关系：`belongs_to_category`、`has_article`、`amended_by`、`supersedes`

## 5. 排除地方法规（重点）

1. 目录级排除：跳过 `地方性法规/`。
2. 标题核验兜底：对纳入目录的文件，用否定规则（标题含「省/市/自治区/自治州…条例/办法/规定」且非行政法规）标记待复核，人工抽查剔除。

## 6. 时效判定（已确认口径）

- 同一法律多版本：取**文件名日期最新**者为「现行有效」；历史版本标「已被修订」并挂 `supersedes`。
- 废止状态：结合沿革正文判定；机器难精判时标「待人工核验」。

## 7. 处理管线

`parse → normalize → extract → KG(Neo4j) → vector(bge-m3) → provenance → Explorer`

- 每个 Article 节点保留条号 + 原文 + 所属法律，写入 Neo4j。
- provenance 以 `文件路径 + 文件日期` 标识，逐条可回溯。
- 条文用 bge-m3（1024 维）向量化，存 FAISS；法律整篇额外一条摘要向量。

## 8. 里程碑

- M0 解析器 + 领域本体 + 地方法规排除规则（含测试）
- M1 元数据入库（法律级 L0：名称/部门/层级/日期/时效）
- M2 条文入库 + Neo4j 建图
- M3 条文向量化
- M4 验证 + Explorer 加载与人工抽查

## 9. 风险

1. 非 `地方性法规/` 目录可能混入省市规定 → 标题核验兜底。
2. 时效「最新=现行有效」需抽查；废止依赖沿革文本，个别需人工。
3. `其他/` 混入攻略类文档 → 甄别剔除。
4. 条文数万，bge-m3 本地 CPU 向量化耗时 → 分批续跑。
